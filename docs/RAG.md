# RAG 实现说明：业务资料与可追溯解读

在同一个项目内导入销售数据，再到「业务资料」添加指标口径或业务规则。资料索引完成后，在「AI 分析助手」选中数据集并开启「参考当前项目业务资料」，生成分析计划、核对检索片段，再确认执行。回答中的 `[S1]` 等编号可以打开本次引用原文。

## 先体验一条完整流程

1. 将 [销售指标说明](../examples/knowledge/销售指标说明.md) 添加到业务资料。
2. 使用已有销售数据，提问：`按区域对比销售额，并说明统计口径`。
3. 检查计划中的维度、指标、聚合方式与引用片段，再确认执行。
4. 点击回答中的引用编号，查看原文；核对下方程序计算的结果表。

还可以问 `净销售额应该怎样统计？`。如果数据中没有退款字段或没有计算净销售额，模型应说明不能把销售额当成净销售额。资料不支持的结论，例如没有区域目标时是否达标，不应被推断为事实。

## 两种检索方式

本项目的 RAG 支持两种检索实现。默认使用中文双字词及英文词的加权关键词检索，界面显示「关键词检索」；配置 Embeddings 服务后可使用语义向量检索。两种方式都将检索片段与计算结果传入模型，并在回答中提供来源引用。

需要语义检索时，在项目根目录的 `.env` 配置支持 OpenAI-compatible `/embeddings` 的服务：

```dotenv
EMBEDDING_MODEL=your-embedding-model
EMBEDDING_BASE_URL=https://your-provider.example/v1
EMBEDDING_API_KEY=your-private-key
```

`EMBEDDING_MODEL` 为空时不调用向量服务。启用后，缺省密钥和地址可复用 `OPENAI_API_KEY`、`OPENAI_BASE_URL`，但服务商必须实际支持向量模型；能调用对话模型不代表能调用 Embeddings。配置更新后重启业务服务，并在资料页重新索引。

资料按最多 700 字符分段，重叠约 100 字符。向量检索使用同一模型生成问题向量，按余弦相似度筛选最多 3 个片段；关键词模式使用问题词命中及逆文档频率加权。配置模型和地址的指纹随索引保存，更换模型后旧向量不参与新模型的检索。

## 状态与数据边界

- TXT / Markdown 仅接受 UTF-8；文件最多 1 MB、正文最多 50000 字符，每个项目最多 40 份资料。
- 索引状态包括处理中、可引用和失败。失败可重试；服务重启时，将未完成的索引标记为失败，避免一直等待。
- 所有资料访问、检索、重建和删除接口先检查项目归属。检索只在当前项目内进行。
- 原文、片段和可选向量保存在现有 JSON / MySQL 快照中，当前没有独立向量数据库，适合单机小规模资料库。
- 删除资料会同时删除其片段和向量，并取消未完成的索引。已完成分析保存引用快照，删除资料后历史快照仍保留。
- 配置外部向量服务后，资料正文与问题会发送到该服务；启用模型解读时，检索到的片段会发送给对话模型。密钥始终留在服务端。
- 文档是参考证据，不是可执行指令。系统提示要求区分计算事实、文档规定和推测；检索和引用不能保证模型回答必然正确。

## 验证范围

[检索测试](../backend/tests/knowledge.test.js)检查分段、项目隔离、无匹配、向量相似度、服务失败、重试及删除竞态。向量服务使用本地模拟接口验证调用和排序，不等于真实模型的语义检索效果评测。

[接口测试](../backend/tests/knowledge-api.test.js)启动独立状态文件和计算服务，验证资料上传、权限拒绝、分析计划、程序计算与 SSE 引用链路。

[浏览器测试](../e2e/knowledge.spec.ts)使用模拟接口，检查资料索引反馈、引用计划、流式引用原文高亮和删除确认。与真实模型的引用正确性、召回质量、复杂业务公式及大量文档性能需要在选定服务和数据上继续评估。
